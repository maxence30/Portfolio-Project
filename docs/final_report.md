# Skillink — Final Project Report

**Project:** Skillink — Student Collaboration Platform  
**Project Type:** Portfolio Project  
**Development:** Individual project

## 1. Results Summary

### Project Overview

Skillink is a web platform designed to help students find other students to collaborate with on projects.

The idea came from a simple problem: students often have project ideas but don't always have all the skills needed to complete them. With Skillink, users can publish their projects, look for specific skills, apply to join projects, and communicate with each other.

My main goal was to develop a functional MVP (Minimum Viable Product) that connects students through a simple and accessible interface.

### Main Features Developed

During the development of Skillink, I worked on several important features:

- **User accounts:** Users can register, log in, and manage their profiles.
- **Project management:** Users can create, view, edit, and delete projects.
- **Applications:** Students can apply to join projects, and project owners can accept or reject applications.
- **Messaging:** Users can communicate through a messaging system.
- **Skills:** Users can add skills to their profiles.
- **Project search:** Users can browse projects and use filters to find opportunities.
- **Ratings:** A rating system allows users to leave feedback after collaborations.

### Results Compared to Initial Objectives

At the beginning of the project, I wanted to build a platform where students could easily find collaborators and manage their projects.

The main functionalities planned for the MVP were implemented, including account management, project publishing, applications, and messaging.

I also worked on additional features such as skills, filters, and ratings to make the platform more useful.

The project helped me understand how a complete web application works, from the interface to the backend and database.

### Technical Results

For the frontend, I used HTML, CSS, JavaScript, Tailwind CSS, and DaisyUI.

For the backend, I used Node.js and created HTTP API routes to handle requests from the frontend.

I used MySQL to store the application's data, including users, projects, applications, and messages.

The application follows a client-server architecture, with the frontend communicating with the backend through HTTP requests and JSON responses.

The main result is a working MVP that demonstrates the core idea of Skillink.

I did not collect formal user satisfaction metrics or performance benchmarks during this project. These would be useful for a future version.

## 2. Lessons Learned

### What Went Well

One of the most positive parts of this project was learning how to connect the frontend, backend, and database together.

Before working on Skillink, I had practiced these technologies separately. Building a complete application helped me understand how they communicate in a real project.

I also improved my understanding of JavaScript, HTTP requests, SQL queries, and authentication.

Another positive point was being able to build different features progressively and test them as I developed the application.

### Challenges Faced

One of the biggest challenges was working with MySQL and understanding the relationships between tables.

At first, connecting the database to the backend and writing SQL queries was not always easy. I had to understand primary keys, foreign keys, and how to organize the data correctly.

Another challenge was managing communication between the frontend and backend. Sometimes an API route worked correctly, but the frontend did not display the expected result.

Debugging these problems helped me understand how to use the browser console, terminal logs, and API requests to identify errors.

Time management was also a challenge because I developed the project alone. I had to work on the interface, backend, database, testing, and documentation.

### How I Solved These Problems

To solve these problems, I tried to work step by step instead of developing everything at the same time.

I tested API routes independently before connecting them to the frontend.

For database problems, I used SQL queries to check the structure and content of my tables.

I also used Git and GitHub to track changes and keep my project organized.

When I encountered errors, I tried to understand their causes before making changes.

### What I Would Improve

If I started the project again, I would spend more time planning the application architecture before coding.

I would also organize the backend into smaller modules from the beginning to make the code easier to maintain.

Another improvement would be to add more automated tests and spend more time testing the application on different screen sizes.

Finally, I would improve the messaging system by using WebSockets to support real-time communication instead of regularly requesting new messages from the server.

## 3. Team Retrospective

### Project Organization

Skillink was an individual project, so I was responsible for the different development stages.

I worked on the project planning, technical documentation, database design, frontend, backend, and testing.

Working alone gave me the opportunity to understand every part of the application, but it also required me to manage my time carefully.

### What Worked Well

Working independently allowed me to make technical decisions quickly and keep a consistent vision for the project.

I was also able to improve my skills in several areas of web development instead of focusing on only one part.

Using GitHub helped me keep track of my work and manage different changes during development.

### What Could Have Been Better

The main difficulty was estimating how much time each feature would take.

Some functionalities required more debugging than expected, which reduced the time available for testing and documentation.

I also realized that developing too many features at the same time can make the project harder to manage.

### Improvements for Future Projects

For my next projects, I would:

- Define clearer priorities between essential and optional features.
- Break large tasks into smaller steps.
- Reserve more time for testing and bug fixes.
- Improve technical documentation throughout development.
- Use a more structured development schedule.

If I work in a team in the future, I would also focus on regular communication, clear task assignments, and code reviews.

## 4. Conclusion

Developing Skillink was an important learning experience for me.

It allowed me to apply the knowledge I gained during my training to a complete web application.

The project helped me improve my technical skills, but also my ability to solve problems, organize my work, and make development decisions.

Even though there are still improvements I would like to make, I achieved my main objective of creating an MVP for a student collaboration platform.

In the future, I would like to improve the user experience, add more tests, and make the application more reliable and easier to maintain.
